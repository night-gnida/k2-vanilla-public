# k2-vanilla — оригинальный Klipper для Creality K2 (base, F021)

[English](README.md) | [Русский](README_RU.md)

Запускает **оригинальный хост klipper3d/klipper** на Creality K2 (база),
заменяя устаревший форк Креалити — при сохранении стоковой ОС принтера и
стоковых прошивок MCU. Автокалировка стола тензодатчиком («PRTouch») и
филамент-система CFS продолжают работать через открытые реализации.

> **Статус: экспериментально.** Комплект собран и проверен офлайн (конфиги
> сверены с исходниками апстрима, синтаксис установщика проверен), но **на
> живом железе ещё не запускался**. Установщик автоматически откатывается на
> сток, если новый хост не поднялся.

---

## 1. Как это устроено

```
┌────────────────────────── плата K2 ───────────────────────────────┐
│  Хост Allwinner T113-i (стоковый OpenWrt/Tina, root)              │
│    ├─ klippy  ← UPSTREAM klipper3d (таг v0.13.0), собирается      │
│    │            на принтере gcc из Entware (c_helper.so)          │
│    ├─ 12 вендоренных K2-модулей (GPL-3, из Jacob10383/kalico):    │
│    │   prtouch (тензодатчик), serial_485, motor_control,          │
│    │   box×5 (CFS), motion_limits, force_stop_homing,             │
│    │   led_idle_manager, power_loss_recovery                      │
│    ├─ Moonraker (СТОКОВЫЙ, не тронут — тот же сокет, Fluidd       │
│    │            переподключается сама)                            │
│    └─ Экран Креалити / display-server (не трогаем; см. §9)        │
│  MCU-платы: СТОКОВЫЕ прошивки Креалити — не перепрошиваются.      │
│    Протокол хост↔MCU согласуется при подключении; современный     │
│    хост с этими MCU проверен стеком Jacob10383.                   │
└───────────────────────────────────────────────────────────────────┘
```

Почему это возможно: K2-модули, написанные для Kalico, **не используют ни
одного kalico-специфичного API** (проверено аудитом: нет `danger_options`,
импорты замкнуты внутри кластера, вызовы ядра идентичны апстриму). Они
переносятся в klipper3d без изменений.

## 2. Что получаем / что теряем

**Получаем**
- Оригинальный актуальный апстрим-Klipper (таг настраивается, по умолчанию
  `v0.13.0` — новейший релизный таг апстрима).
- Открытые замены всего, что Креалити держало закрытым: датчик стола, CFS,
  хуки настройки закрытого контура моторов.
- Путь обновления = обычное обновление тага/тарбола; никаких закрытых блобов.

**Сохраняем**
- Стоковую ОС, стоковые прошивки MCU, стоковые Moonraker/Fluidd (:4408),
  стоковый каталог конфигов не тронут (новые конфиги живут в `config-vanilla/`).
- Откат на сток klippy одной командой в любой момент.

**Теряем / нюансы**
- Экран Креалити может глючить (его display-server ждёт форкнутый klippy).
  Если так: остановить `display-server`, пользоваться Fluidd/Mainsail или
  [HelixScreen](https://helixscreen.org).
- KAMP и timelapse пока не включены.
- Power-loss recovery — реализация Kalico (в апстриме её нет) —
  вендорена здесь, но на этом принтере менее обкатана.
- Макросы камерного нагрева (`M141`/`M191`) — заглушки «нет нагревателя».
  Если позже физически поставишь PTC-блок от K2 Pro (цепи на плате те же),
  макросы нужно будет переделать на Pro-вариант.

## 4. Требования

- Creality **K2 base (F021)** на **стоковой прошивке**, включён рут
  (меню принтера → Root-аккаунт → пользователь `root`, пароль `creality_2024`).
- На принтере установлен **Entware** (даёт gcc, make, python3, pip).
- Интернет на принтере (скачивается тарбол Klipper с codeload.github.com).
- Присутствует стоковый init-скрипт klipper (`/etc/init.d/klipper` и т.п.).

Комплект собран под базу (F021: стол 260×260, одиночный Z с редуктором 64:20,
TMC2208 на PC1, без камерного нагревателя). K2 Pro делит плату, но не
геометрию — как есть не использовать.

## 5. Установка

**На ПК** (репозиторий приватный — принтер сам его не скачает):

```bash
scp -r k2-vanilla root@<IP_ПРИНТЕРА>:/mnt/UDISK/k2setup/
```

**На принтере** (SSH под root):

```bash
sh /mnt/UDISK/k2setup/k2-vanilla/scripts/install.sh
```

Что делает скрипт по шагам:

1. Ставит пакеты Entware: `gcc make python3 python3-pip python3-dev libstdc++`.
2. `pip install --target /mnt/UDISK/klipper-vanilla-deps greenlet` (без venv —
   используется Entware-python напрямую).
3. Скачивает тарбол исходников Klipper и распаковывает в
   `/mnt/UDISK/klipper-vanilla`. Версия фиксируется переменной
   `K2_VANILLA_KLIPPER_TAG=vX.Y.Z` (по умолчанию `v0.13.0`).
4. Копирует `files/*.py` в `klippy/extras/` (вендоренные модули).
5. Копирует `config/*.cfg` в `/mnt/UDISK/printer_data/config-vanilla/` —
   стоковый каталог конфигов **не трогается**.
6. Определяет аргументы сокетов (`-I`, `-a`) из стокового init-скрипта klipper,
   чтобы Moonraker/Fluidd переподключились прозрачно.
7. Создаёт procd-службу `/etc/init.d/klipper-vanilla`, отключает стоковую
   службу klipper, запускает vanilla.
8. Ждёт до 90 с строки `Printer is ready` в логе. При ошибке конфига или
   таймауте **автоматически откатывается** на сток и печатает хвост лога.

При успехе: `VANILLA KLIPPER IS UP`. Fluidd переподключается сама.

## 6. Переключение и откат

```bash
sh .../install.sh status     # что сейчас активно
sh .../install.sh revert     # назад на сток Креалити (файлы vanilla остаются)
```

`revert` снова включает стоковую службу и запускает её; файлы vanilla
остаются на `/mnt/UDISK` для повторной попытки, удалить их можно вручную.

## 7. Первые движения — чеклист безопасности

Первые запуски — с рукой на выключателе:

1. Хоминг X/Y — голова уходит влево/назад к концевикам PB11/PB12 на малой скорости.
2. `G28 Z` — сопло едет в центр стола (130,130) и **медленно** ищет стол
   тензодатчиком. Это первый живой тест PRTouch на апстримном Klipper.
3. Убедись, что вентиляторы/подсветка реагируют адекватно.

Если что-то поехало не туда — выключай питание; ничего важного не потеряется.

## 8. Проверка железа и калибровка

- **Датчик**: выполнить `PROBE` несколько раз — разброс в сотых долях мм.
- **CFS**: бокс должен появиться в Fluidd (`box_count: 1`). Попробовать
  load/unload. **`CALIBRATE_CUT_POS` обязателен до первой смены филамента.**
- **Координаты с пометкой `VERIFY`** в `box.cfg` (края площадки и верстак
  выведены из заводских значений и требуют проверки глазами на принтере):

  | Параметр | Значение | Источник |
  |---|---|---|
  | `clean_pad_left_x` / `right_x` | 127 / 137 | заводской F021 `box.cfg` |
  | `clean_pad_front_y` / `back_y` | 286.5 / 296.5 | оценка от заводской середины полосы y=291.5 |
  | `wastebin_pos_x` / `y` | 115 / 294 | заводская точка выгрузки, оценка |
  | `cut_pos_y`, `pre_cut_pos_x` | 150 / 10 | заводские |
  | окно калибровки резака | x −5.5…−9.5 | проверено на Плюсе, уточнить через `CALIBRATE_CUT_POS` |

- **Порядок калибровки** (методика k3d.tech):
  `SCREWS_TILT_ADJUST` (винты 30/230) → `BED_MESH_CALIBRATE
  PROFILE=default` → `PROBE_CALIBRATE` → `BEDPID` + `NOZZLE_PID` → входной
  шейпер (акселерометр lis2dw) → поток → pressure advance. Экструдер с
  закрытым контуром: сначала `MOTOR_ENCODER_CALIBRATE`, иначе результаты PA
  будут загрязнены диагональными артефактами.

## 9. Устранение проблем

| Симптом | Действие |
|---|---|
| Установщик откатился | Читать напечатанный хвост лога klippy; править `config-vanilla/*.cfg`; запустить `install.sh` снова (шаги идемпотентны). |
| greenlet не собрался | Нет заголовков python в Entware: `opkg install python3-dev`; проверить наличие `gcc`. |
| Fluidd не переподключается | Проверить пути `-I`/`-a`, которые вычислил скрипт: `grep -E '\-I|\-a' /etc/init.d/klipper-vanilla`; сверить со стоковым init-скриптом и `klippy_uds_path` в Moonraker. |
| Глючит экран | `/etc/init.d/display-server stop` (имя службы может отличаться); пользоваться Fluidd или HelixScreen. |
| Принтер странно себя ведёт после OTA Креалити | OTA работает со стоковым слотом/службой — выполнить `install.sh status`, при необходимости повторить установку. |

## 10. FAQ

**Почему нельзя просто заменить klippy внутри стокового форка?**
Стоковый хост — старый форк (~v0.12), сваренный с закрытыми блобами:
`prtouch_v3` (.o), RS485 msgblock, EEPROM-модуль, привязка к master-server.
Апстрим их не загрузит, форк не обновить. Этот комплект меняет хост целиком
и возвращает недостающие функции открытым кодом.

**Почему прошивки MCU остаются стоковыми?**
Весь «мозг» Klipper живёт на хосте. Прошивки MCU говорят по протоколу,
который согласуется при подключении; перепрошивка плат GD32 ванильными
сборками — риск без пользы. Здесь MCU не трогается вообще.

**Почему включён `[power_loss_recovery]`, если в апстриме такой секции нет?**
В klipper3d действительно **нет** модуля PLR. Реализация Kalico вендорена
(чисто апстримный API, проверено аудитом), поэтому секция в `printer.cfg`
работает.
