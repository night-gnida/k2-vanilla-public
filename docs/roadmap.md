# МАСТЕР-ПЛАН k2-vanilla — единый сводный документ (консолидация 2026-09-09)

В этом файле собраны ВСЕ планы проекта: цель, состояние, принятые решения,
этапы с шагами, риски и критерии готовности. Живой журнал исполнения —
`docs/stage1-log.md` (история, не план). Прежние разрозненные планы
(чек-лист первой печати, мини-планы из чатов) слиты сюда.

**Формула проекта:** хост — апстрим klipper3d v0.13.0; MCU — сток Creality
(никогда не перепрошиваются); ОС — сток OpenWrt/T113-i; Kalico — вырезан
(ноль зависимостей, только происхождение GPL-драйверов); откат на сток —
одна команда.

**Конечная точка:** работающий K2 base (F021) на ванильном Klipper с набором
улучшений, отсутствующих в стоке (быстрый старт, надёжность, мониторинг/UI,
скорость/качество).

**Режим работы с железом — «гибрид»:** по SSH без вопросов — статус, деплой
файлов, рестарт klipper через procd; движение, нагрев, старт печати — только
по явному ОК (юзер рядом с кнопкой питания; M84 после тестовых движений).

## 5. Эксплуатационные грабли (влияют на планирование)

1. **Zombie klippy**: `killall klippy.py` не работает (comm = «python»);
   рестарт только через procd-инит; маркер ванили — arcs 1.0.
2. **UDISK FTL stale pages**: перезаписанный файл минутами читается смесью
   страниц → критичное в новые имена файлов, md5-верификация перед
   рестартом (install.sh делает сам).
3. **485-шина капризна**: потеря пакетов (func 0x08/0x0C на X-моторе);
   все критичные команды — с ретраями 5×2 с; флейк «Endstop still
   triggered» после загрузки — повторить.
4. **GD32-самохалт**: трип защиты мотора вешает UART до power-cycle для
   ЛЮБОГО хоста → профилактика (1.6) обязательна перед длинными печатями.
5. **Питание юзера**: «пропал из сети» = свет, не поломка; чекпоинтить
   состояние перед движениями.
6. **remote.py push** кладёт файл под ЛОКАЛЬНЫМ именем; MSYS_NO_PATHCONV=1
   обязателен; /tmp с задержкой видимости — хелпер держать на UDISK.
7. **Z = стол движется ВВЕРХ к соплу** (не голова). Формулировки и
   направления — только через это.
8. **Экран/master-server**: не запускать калибровки с экрана во время
   печати (сток шлёт G29 и ждёт [G29_TIME]-хендшейк).
9. **Сенсорному хомингу нужна скорость**: при 20 мм/с сталл-детекция даёт
   ложные срабатывания («Endstop y still triggered after retract» —
   проверено живьём 2026-09-09). Штатные 100/50 + доставленный stall-mode
   (DATA=1, param-write с ретраями) = мягкий хоминг 2–8 с. Рецепт:
   MOTOR_CLEAR_ERROR → DATA=2 (сброс защёлок) → DATA=1 → G28; руками
   каретку в mode 1 не толкать (залипает защёлка).
